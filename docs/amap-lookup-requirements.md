# 高德地图检索：数据需求

在高德上查地点时，按这份说明记录。记下的信息会用在网页的大地图、店铺 popup、「在高德打开」按钮和行程上，同时也要符合[知识库的来源规则](../data/知识库/README.md)：写明是从哪里查到的、哪天查的；不确定是不是同一家时，不写进正式地址。

待查的地点和街区已经列在[高德检索清单](../data/知识库/发现与待补充/高德检索清单.csv)里，用 Excel 可以直接打开填写。

清单里 `记录类型` 为「待识别线索」的行，知识库里还没有对应的地点资料：名称来自作者回复、视频画面、评论或点点 AI，写法可能不准，`待核实提示` 里写了线索来源和建议的搜索词。查到时按地点的字段照常填。这类行的「确认」只表示高德上的地点就是线索里说的那家店，不代表它一定是帖子里出现的店；`匹配依据` 要写明线索来自作者、画面还是 AI。

## 每个地点记什么

| 字段 | 是否需要 | 怎么填 | 网页用在哪里 |
| --- | --- | --- | --- |
| 知识库名称 | 必填 | 照抄清单里的名称，不要改。 | 对应到已有的地点资料。 |
| 高德名称 | 必填 | 照抄高德显示的完整名称，括号里的分店名也要抄，例如「绿洲Oasis(江汉路咸安坊店)」。 | 区分分店。 |
| 高德链接 | 必填 | 网页版就复制地址栏，形如 `https://ditu.amap.com/place/B0FFK4IHIB`，`B0FFK4IHIB` 是这个地点的 POI 编号。App 里「分享 → 复制链接」也可以，我来解析；解析不出来会请你补网页链接。 | 「在高德打开」按钮；之后用来批量取坐标。 |
| 地址 | 必填 | 照抄高德的地址。 | popup 里显示。 |
| 分店匹配 | 必填 | 只填「确认 / 不确定 / 找不到」之一，判断方法见下一节。 | 只有「确认」的地点会上地图。 |
| 匹配依据 | 必填 | 一句话说明为什么这样判断。 | 写进来源，方便以后复查。 |
| 查询日期 | 必填 | 例如 `2026-11-25`。 | 显示「某天查询」，提醒出行前复查。 |
| 营业状态 | 建议 | 正常 / 暂停营业 / 已关闭 / 高德未标注。 | 已关闭的不推荐。 |
| 营业时间 | 建议 | 照抄高德，休息日也抄上，例如「周二至周日 10:00-20:00，周一休息」。 | 排行程、判断现在开没开。 |
| 楼层或入口 | 建议 | 例如「1F」「从鄱阳街进」。在商场或里弄里的店尤其需要。 | 到了现场好找。 |
| 人均 | 可选 | 照抄高德显示的「¥/人」。 | popup 里作参考，会注明查询日期。 |
| 备注 | 可选 | 例如「高德上有三家同名店，候选见下」。 | 留给后续核实。 |

**不需要记的：**

- **坐标。** 高德 App 不直接显示经纬度。有了 POI 编号以后，可以用高德开放平台的 Web 服务 API 批量取（需要你的高德 Key）；个别地点也可以用高德开放平台的坐标拾取器手动查。坐标统一用高德的 GCJ-02 坐标系。
- **高德上的评分和评论。** 网站是公开的，不转载别人的评论。
- **店铺电话。** 网页暂时用不到。

## 分店匹配怎么判断

| 状态 | 什么时候选 | 怎么处理 |
| --- | --- | --- |
| 确认 | 高德名称或招牌与帖子一致，并且帖子提到的街道、商场、楼层能对上；或者武汉只有一家、名字完全一致。 | 写入地点的正式地址，会在地图上显示。 |
| 不确定 | 高德上有多家同名店，帖子无法分辨是哪一家；或者名字相近但不完全一致。 | 每家候选都记下高德名称和链接，先不写正式地址。 |
| 找不到 | 高德搜不到，或者显示已关闭。 | 记下搜过的关键词，留给之后再查。 |

「依据」要写具体，例如「帖子图 3 有黎黄陂路路牌，高德只有这一家在黎黄陂路」。不要只写「应该是」。

## 每个街区记什么

街区（知识库里的「目的地」）是给首页大地图定位用的，不需要精确到门牌。

| 字段 | 是否需要 | 怎么填 |
| --- | --- | --- |
| 高德名称和链接 | 必填 | 在高德搜街区名。有街区本身的 POI 就记它；没有就记一个能代表这片的地点，并在备注里说明。 |
| 所在三镇 | 必填 | 汉口 / 汉阳 / 武昌。 |
| 行政区 | 必填 | 从地址里看，例如江岸区。 |
| 大致范围 | 可选 | 四周的几条路名，例如「中山大道、沿江大道、黎黄陂路、兰陵路之间」。画插画地图的形状时用。 |

## 怎么把结果给我

三种方式都可以，选最顺手的：

1. **填清单表。** 在 `高德检索清单.csv` 里填好后告诉我。
2. **在手机上发文字。** 每个地点按下面的格式发一段：

   ```text
   知识库名称：香钿 DIAN
   高德名称：
   高德链接：
   地址：
   营业状态：
   营业时间：
   楼层或入口：
   分店匹配：确认 / 不确定 / 找不到
   匹配依据：
   查询日期：
   ```

3. **只发链接和截图。** 每个地点发高德链接和详情页截图，再说一句是不是同一家、为什么。其余信息我来抄。

收到后由我整理写入知识库，只写高德上实际看到的内容。

## 写入知识库的格式（建议）

为了不打乱现有结构，`地址` 保持现在的格式，另外加一个 `高德` 字段记录查询结果，`坐标`、`开放时间`、`营业状态` 也都带上来源和查询日期。下面以巴公房子为例；它的地址已经从高德查到，其余还没查的保持 `null`：

```json
{
  "高德": {
    "名称": null,
    "POI": "B0FFK4IHIB",
    "链接": "https://ditu.amap.com/place/B0FFK4IHIB",
    "分店匹配": {"状态": null, "依据": null},
    "候选": [],
    "查询方式": "通过网页检索读取页面，可能为缓存",
    "查询日期": "2026-11-25"
  },
  "地址": {
    "内容": "武汉市江岸区大智街办事处洞庭街73号",
    "楼层或入口": null,
    "状态": "高德地图页面所列，出行前待复查",
    "来源": {"平台": "高德地图", "链接": "https://ditu.amap.com/place/B0FFK4IHIB", "查询方式": "通过网页检索读取页面，可能为缓存"},
    "查询日期": "2026-11-25"
  },
  "坐标": {"经度": null, "纬度": null, "坐标系": "GCJ-02", "来源": null, "查询日期": null},
  "开放时间": {"内容": null, "来源": null, "查询日期": null},
  "营业状态": {"内容": null, "来源": null, "查询日期": null},
  "人均": {"内容": null, "来源": null, "查询日期": null}
}
```

- `分店匹配` 不是「确认」时，`地址.内容` 保持 `null`，候选写进 `高德.候选`。
- 营业时间、营业状态和人均都会变，网页上会显示查询日期，并提示出行前复查。
- 这些字段名是建议，确认后再批量补到所有地点。
