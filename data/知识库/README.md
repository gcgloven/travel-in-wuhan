# 武汉旅行知识库（初版）

这个知识库以「目的地概念 → 具体地点 → 每日行程」组织。它依据目前已观察的小红书资料整理；提取和审核仍在进行，空字段和待核实事项不代表地点不存在。原始记录保留在 `../xiaohongshu/posts.jsonl`，不要以这里的整理结果覆盖原始记录。

## 目录

- `目的地/名称/资料.json`：商圈、街区、景区等概念，保存简介及关联地点名称。一个地点可关联多个目的地；边界不确定时不要强行归类。
- `地点/名称/资料.json`：店铺、景点等唯一的地点资料。每个地点只维护一份；同名不同分店先核实，不要仅凭名称合并。
- `路线/`：来自帖子或之后自行规划的路线。来源路线不是已验证的导航路线。
- `发现与待补充/`：地图发现、身份待识别的线索及等待用户收集小红书资料的推荐。推荐不等于用户已收藏或认可。
- `待识别-餐饮.json`：已有帖子中店名或分店尚未确认的线索。合集帖在 `线索` 里逐项记录名称、依据（作者、画面、评论者或点点 AI）、位置说法和备注；AI 线索未经核实。
- `行程/`：将来按日期建立行程；引用地点资料，不复制为新的事实。
- [规划索引 v2](规划索引-v2.json) 的「双年展行程」提供七个片区的餐饮、五天四夜动线、展馆及票务核对。每日活动引用原地点编号和本次餐饮编号；门店营业详情可从记录里的高德链接查看，步行分钟数为行程预留。

`发现与待补充/提取与整理待办.json` 是生成时的帖子关联快照，并非实时进度；继续审核时应以原始 `posts.jsonl` 为准。地点中的 `来源专题` 表示帖子清单的主题，不代表分店或地点归属已经确认。

文件使用 UTF-8 JSON 和中文字段。`null` 表示未知或未填写，空数组表示目前没有收录；`待核实` 记录下一步要查的内容。`所属目的地` 是概念关联，不证明地点的准确位置或行政归属。`图片` 仅记录实际保存的文件及来源，目前未归档的原图不会伪造。

## 来源与更新

地点的 `来源` 包含平台、帖子编号和依据，可通过 `https://www.xiaohongshu.com/explore/<帖子编号>` 回到帖子，并在原始记录中查看审核进度。帖子可能只审核了部分内容；来源提及、图片所见、作者个人评价和独立核实应分别表述。价格、营业时间、入口等会变化的信息必须记录来源与查询日期，不应把旧说法写成当前事实。

后续流程：发现候选地点 → 用户决定是否收藏相关小红书页面 → 提取到原始记录 → 与地点资料匹配并补充来源、图文及待核实事项 → 按需要核实地址与时间 → 加入每日行程。相同名称但分店不明时保留为候选，不要自动合并。发现新的关联或纠正旧信息时保留证据与未解决的冲突。

## 地图信息

地图结果应记录具体名称、地址、来源链接或可复现的搜索词、查询日期和分店匹配情况。地图所列信息只代表查询时观察到的内容；无法确认与帖子为同一地点时，不能直接写入已有地点地址。没有亲自查询到的地图结果不要标成已核实。
